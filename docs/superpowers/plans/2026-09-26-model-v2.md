# Model v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the game model use more history, richer pregame rating features and tuned or ensembled models, and add a `psu experiment` harness that proves which changes help before they ship.

**Architecture:**
- **Features:** the rating pipeline is generalised from two hard-coded metrics (EPA, success rate) to a metric registry with optional in-season recency weighting. `assemble_features` also emits `d_elo`.
- **Models:** each model carries its own feature list and hyperparameters, and fitting accepts per-season sample weights.
- **Harness:** a new `psu.experiment` module runs a walk-forward over test seasons 2023–2025 with paired-bootstrap intervals and greedy staged selection.
- **Production:** `psu train` and backfill read a `ModelConfig` from `psu.config`.

**Tech Stack:** Python 3.11+, pandas, numpy, scipy, scikit-learn (Ridge only), xgboost, DuckDB, pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-09-26-model-v2-design.md`

## Global Constraints

- Never add the Vegas line as a model feature (`vegas_margin` is for comparison only).
- No new dependencies. Never import `sklearn.impute` or `sklearn.neighbors` (Smart App Control).
- Every feature for a game uses only information from before its slate.
- No live CFBD calls in tests. Do not run `psu` against `data/psu.duckdb` in tasks; the orchestrator does real runs.
- The tuned defaults `config.TRAIN_ALPHA = 20.0` and `config.SHRINK_PLAYS = 75` stay as they are.
- Default behaviour must not change until Task 5 flips `MODEL_CONFIG`: with the default configuration, features and predictions match today's exactly.
- Style: ruff, line length 120. Run `.venv/Scripts/ruff check .` and `.venv/Scripts/ruff format --check .`.
- Tests: `.venv/Scripts/python -m pytest -q` must pass fully at the end of every task.
- Commits: one Conventional Commit per task. The message ends with a blank line, then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage by explicit path.

## Review Focus

1. **Default equivalence.** With the default metrics ("epa", "sr") and no recency weighting, `rolling_ratings` and `assemble_features` output is identical to before, and so are `game_predictions`.
2. **Leakage in the new metrics.** Explosive, rush EPA and pass EPA ratings for slate s use only plays from slates < s, and recency weights never look forward.
3. **Old saved models.** A pickled `GameModel` without a `features` attribute still predicts, using the old `FEATURES`.
4. **Experiment walk-forward never trains on the test season.** Inner tuning never sees the outer test season.
5. **Season weights.** A weight of 0 drops the season. Weights reach both the Ridge and the XGBoost fits and the out-of-fold sigma.

**Files:**

**Interfaces:**
- Consumes (Task 1): `opponent_adjust(..., weights=)` and the `"explosive"` value.
- Produces, in `psu.features`:

```python
METRICS: dict[str, tuple[str, str | None]] = {  # name -> (adjusted value column, play_class filter)
    "epa": ("ppa", None),
    "sr": ("success", None),
    "expl": ("explosive", None),
    "rush_epa": ("ppa", "rush"),
    "pass_epa": ("ppa", "pass"),
}
DEFAULT_METRICS = ("epa", "sr")


def rating_columns(metrics=DEFAULT_METRICS) -> list[str]:
    """["off_epa", "def_epa", "off_sr", "def_sr", ...] -- off/def per metric, in metric order."""
```

  - `RATING_COLUMNS = rating_columns()` is unchanged in value.
  - `league_means(enriched, metrics=DEFAULT_METRICS) -> dict[str, float]` returns one key per metric: the mean of that metric's value over non-garbage plays passing its filter.
  - `season_ratings(enriched, alpha, metrics=DEFAULT_METRICS, weights: str | None = None)` returns the rating columns for those metrics plus `off_plays` and `def_plays`. The play counts come from the first metric in the list.
    - Each metric adjusts only the plays passing its `play_class` filter. Rush and pass metrics use their own filtered play counts for shrinkage, returned internally.
    - Rule for the blend: in `_ratings_at`, a metric's `n` is its own off or def play count, so `season_ratings` must expose per-metric counts as `off_plays_<metric>` and `def_plays_<metric>`.
    - The `epa` and `sr` counts equal today's `off_plays` and `def_plays`, which are kept for compatibility.
  - `_ratings_at(..., metrics, half_life)` changes as follows:
    - When `half_life` is not None, plays get `w = 0.5 ** ((slate - play_slate) / half_life)` in a column `_w`, passed as `weights="_w"`.
    - The shrink blend uses the weighted counts.
    - The prior (last season's finals) is always unweighted.
  - `rolling_ratings`, `ratings_as_of` and `frozen_ratings` gain `metrics=DEFAULT_METRICS, half_life: float | None = None` keyword arguments and thread them through. `frozen_ratings` takes the column list from `snapshot.columns`.
  - `assemble_features(ratings, games, lines, sp, talent)`:
    - It computes `d_<col>` for every rating column present in `ratings`, not only `RATING_COLUMNS`.
    - It also computes `d_elo = home_pregame_elo - away_pregame_elo` when those columns exist in `games`, and NaN otherwise.
    - It returns `GAME_COLUMNS` plus every `d_*` column, `home_field`, `d_prior_sp`, `d_talent` and `d_rest`, so any feature subset can be selected later.
  - `ALL_FEATURES`, the list of every feature name assemble can emit, is used for validation in Task 4.
  - `FEATURES` is unchanged, the current 8 names.
  - `game_features(..., metrics=DEFAULT_METRICS, half_life=None)` passes both through.
- `train.load_feature_inputs`: the games query also selects `home_pregame_elo` and `away_pregame_elo`. Use `try`/fallback if the columns are missing in an old DB: check `information_schema.columns` and select NULL AS ... when absent.

### Task 3: Models that carry their feature list, parameters, weights and an ensemble

**Files:**
- Modify: `src/psu/models/game_predict.py`
- Test: `tests/test_game_predict.py`

**Interfaces:**
- Produces:
  - `MODEL_KINDS = ("linear", "xgboost", "ensemble")`. `backtest`'s validation choice still compares only `("linear", "xgboost")`; call that `BASE_KINDS`.
  - `make_pipeline(kind, params: dict | None = None)`:
    - For `linear`, Ridge uses `params.get("alpha", 1.0)`.
    - For `xgboost`, the defaults are today's (n_estimators 300, max_depth 3, learning_rate 0.05, subsample 0.8, random_state 0, n_jobs 1), overridden by `params`.
    - `ensemble` is not a pipeline (see below).
  - `@dataclass class GameModel` gains fields, each with a default:
    - `features: tuple[str, ...] = tuple(FEATURES)`
    - `params: dict | None = None`
    - `members: list[GameModel] | None = None`
    - `predict_margin` uses `df[list(self.features)]`; for `kind == "ensemble"` it returns the mean of the members' `predict_margin`.
    - Add `__setstate__`, or use `getattr(self, "features", FEATURES)`, so models pickled before this change (no `features` attribute) still work. Test this by building a model, deleting the attribute, and predicting.
  - `fit(train, kind, *, features=FEATURES, params=None, weights: pd.Series | None = None) -> GameModel`:
    - It uses the `features` columns.
    - `weights` is aligned to `train`'s index and passed as `model__sample_weight` to the pipeline fit and to `cross_val_predict` via `params={"model__sample_weight": w}` (scikit-learn ≥1.4 API; fall back to `fit_params=` if needed).
    - The out-of-fold sigma is the weighted SD of residuals.
    - Rows with weight 0 are dropped before fitting.
    - For `ensemble`, `params` is `{"linear": {...}, "xgboost": {...}}`. It fits both members, and sigma is the SD of the averaged out-of-fold predictions' residuals.
  - `tune(train, kind, grid: list[dict], *, features, weights=None) -> dict`:
    - It does inner walk-forward selection within `train`'s own seasons: for each inner season after the first two, fit on the earlier ones and score MAE.
    - It returns the params with the lowest mean MAE. With fewer than 3 seasons, it returns `grid[0]`.
  - `LINEAR_GRID = [{"alpha": a} for a in (0.3, 1.0, 3.0, 10.0)]`.
  - `XGB_GRID` is the product of n_estimators (300, 600), max_depth (2, 3, 4), learning_rate (0.03, 0.06) and min_child_weight (1, 5), as dicts.
  - `backtest(features, current_season, team, *, model_features=FEATURES, weights=None)` fits with those features. Everything else stays as today.

### Task 4: `psu experiment` harness

**Files:**
- Create: `src/psu/modelconfig.py`, `src/psu/experiment.py`
- Modify: `src/psu/cli.py` (the `experiment` subcommand)
- Test: `tests/test_experiment.py`, `tests/test_cli.py`

**Interfaces:**
- `psu.modelconfig`:

```python
@dataclass(frozen=True)
class ModelConfig:
    features: tuple[str, ...] = tuple(FEATURES)
    model: str = "select"  # "select" = today's rule: linear vs xgboost on validation MAE
    params: dict | None = None  # None = defaults; "tuned" handled by experiment/train via tune()
    tune: bool = False
    train_from: int = 2020
    season_weights: tuple[tuple[int, float], ...] = ()  # e.g. ((2020, 0.5),); weight 0 drops a season
    metrics: tuple[str, ...] = DEFAULT_METRICS
    half_life: float | None = None

    def validate(self) -> None: ...  # unknown feature / metric / model -> ValueError
    def weight_of(self, season: int) -> float: ...
```

  - A config's features may include any name in `ALL_FEATURES`. Validation checks that the `d_<rating col>` names need their metric in `metrics`.
- `psu.experiment`:
  - `TEST_SEASONS = (2023, 2024, 2025)`.
  - `walk_forward(frame, cfg, test_seasons=TEST_SEASONS) -> pd.DataFrame` returns one row per completed test game, with `season, slate, season_type, margin, pred, prob`. For each T:
    1. Train on completed rows with `cfg.train_from <= season < T`, using `weight_of`.
    2. If `cfg.model == "select"`, choose linear or xgboost on the last training season as validation, as `backtest` does. If `cfg.tune`, run `tune` inside the training rows.
    3. Fit, predict T, and compute `prob = NormalCDF(pred / sigma)` from the fitted model's pooled sigma.
  - `score(pred_frame) -> dict` returns `mae`, `early_mae` (regular season, slate ≤ 4), `brier` and `n`.
  - `paired_delta(ref, cand, *, n_boot=2000, seed=0) -> tuple[float, float, float]` returns the mean, the 5th and the 95th percentile of the per-game abs-error difference (cand − ref), bootstrapped over games joined on game_id. The predictions frame must carry `game_id`.
  - `adopt(ref_scores, cand_scores, delta) -> bool` returns `delta_mean <= -0.02 and cand_brier <= ref_brier + 0.0005`.
  - `run(con, *, out_dir) -> dict` runs the spec's stages:
    1. Build or cache feature frames per `(metrics, half_life)` with `game_features`, using `config.TRAIN_ALPHA` and `config.SHRINK_PLAYS`. Metrics for all stages: `("epa", "sr", "expl", "rush_epa", "pass_epa")` with half-life None, 4 or 8. Compute all five metrics once per half-life; columns a config doesn't use are ignored.
    2. Stage D: B0 (defaults, train_from 2020), D0 (train_from 2022), D1 (2020 weight 0), D2 (2020 weight 0.5). The best adopted config becomes the reference; D0 is compared with B0.
    3. Stage F: add F1 `d_elo`; F2 `d_off_expl, d_def_expl`; F3 the four rush and pass diffs; F4a half_life 4; F4b half_life 8. Try each alone on the reference, then the union of the adopted ones.
    4. Stage M: M1 `model="linear", tune=True`; M2 `model="xgboost", tune=True`; M3 `model="ensemble", tune=True`, where ensemble tuning tunes each member separately.
    5. Write `experiments.md` and `experiments.json` to `out_dir/reports`. Each has one row per candidate (name, stage, reference, mae, early_mae, brier, delta [lo, hi], adopted), plus the final chosen config as a dict.
    6. Return the report dict.
- CLI `psu experiment`:
  - It prints the markdown and the final config.
  - It exits 2 with a message when there are fewer than 2 training seasons before 2023: check `min completed season` and `train_from`.
  - It never writes `game_predictions`.
  - It may take several minutes, so log each candidate with `log.info`.
